# Adaptive Create Page — Design Spec (SP1)

**Date:** 2026-06-13
**Status:** Approved design, pre-implementation
**Repos:** `echome-frontend` (the page), `echome-platform-v2` (the KB-advisor endpoint)
**Sub-project:** SP1 of 3. SP2 = long-form video library + per-item routing + dimension classifier (BE). SP3 = autopilot kit engine + AI scheduling + confirm-then-post (BE, on Echo v2).

---

## 1. Purpose

The `/app` Create page is the front door to the entire product. It is **not** only a content-creation input — it is also the knowledge-base (KB) ingestion front door. Because it replaces the whole surface, it must **route the user by the condition of their KB**: if the KB is thin, nudge them to feed it (especially by voice); if rich, surface what Echo can already make for them, trending toward autopilot.

The page is an **adaptive surface**: one page, three states, chosen server-side from KB dimension coverage. The intelligence (which nudge, which proposals) is **agentic** — generated by a model against EchoMe's content methodology — but precomputed and cached so the page never blocks on a model call.

### Founder vision this serves
- Lead users to the **voice button** — talk for a few minutes; teach the payoff that more KB input = more content Echo makes unprompted.
- KB is a full personal profile: work, industry/area, interests, personal, family/friends, voice — not just facts about the user.
- North star: dump raw material in → Echo on autopilot builds kits → AI schedules → user confirms → posts.

### Operating tenets in play
Chat First, Low UI, Feature Rich Low UI, Context Is King, No Onboarding, Work Before The Work.

## 2. Architecture overview

```
Page load (echome-frontend)
  → GET /api/kb/advisor   (echome-platform-v2, GA, read-only)
       → returns cached {state, coverage, nudge, proposals}
       → cache keyed by user_id + kb_hash; recomputed on KB change
       → deterministic gate is the cold-cache / model-down fallback
  → AdaptiveCreateSurface picks state (empty | thin | rich) → renders
```

**Two layers, never one synchronous model call on load:**

- **Layer 1 — the gate (deterministic, instant, free):** which state to show. Pure computation from coverage data. Runs server-side; safe fallback when the cache is cold.
- **Layer 2 — the intelligence (agentic, precomputed, cached):** the actual personalized nudge copy and rich-state proposals. Generated asynchronously after KB-change events, read from cache on load.

**Hybrid brain:** SP1 ships a lightweight, read-only **KB-advisor** service that is GA for all users from day one (independent of the Echo v2 admin soak). Its response is a **stable contract**. Later (SP3) the Echo v2 agentic engine becomes the *producer* of that same contract and graduates proposals from "suggest/prefill" to "stage a full kit" — with zero frontend rework.

## 3. Dimension taxonomy (the gate signal)

KB richness = **breadth across six life dimensions**, not raw volume.

| Dimension | Meaning | Tier-1 signal (now) | Tier-2 signal (SP2) |
|---|---|---|---|
| **Work** | What they do | `users.profile_role`, `profile_topics`, `public_profiles` | (reliable now) |
| **Industry/area** | Their field/market | `voiceContext.recurringThemes`, topic spread | per-ingest classifier |
| **Interests** | Passions outside work | coarse / weak | per-ingest classifier |
| **Personal** | Life, story, values | `voiceContext.coreBeliefs`, conversational chunks | per-ingest classifier |
| **Relationships** | Family/friends | none today | per-ingest classifier |
| **Voice/style** | How they sound | voice-recording + writing-sample count, `voice_profiles` present | (reliable now) |

**Advisor owns dimension classification.** Frontend never computes coverage — it renders the advisor's `coverage` object. Two-tier rollout: tier-1 (Work + Voice reliable, other four coarse) ships SP1; tier-2 (per-ingest dimension tagging) ships in SP2 and sharpens the same fields without FE changes.

**State thresholds (tier-1 starting point, tunable):**
- `empty` — 0–1 dimensions covered
- `thin` — 2–3 dimensions covered
- `rich` — 4–6 dimensions covered

"Covered" = `strength >= 0.2` for that dimension (has meaningful material). Final thresholds tuned against real staging accounts during smoke.

## 4. The three page states

### EMPTY (0–1 dims) — feed-me mode
- Hero leads with the **voice button** as the primary CTA. Headline teaches: e.g. "Teach Echo your voice — talk for two minutes."
- Subhead = the payoff lesson: the more you tell Echo, the more it makes for you beyond what you ask.
- Capability tiles demoted, reframed as "here's what you'll be able to make."
- CoverageMeter prominent — visibly empty, an invitation.

### THIN (2–3 dims) — balanced
- Composer and voice button both prominent.
- AdvisorNudgeCard names the gap: "Covered Work + Voice. Tell me about your interests and family so I can make content beyond your day job." Actions are ranked and specific.
- A few draftable suggestions from existing material. Capability tiles = "or make something now."

### RICH (4–6 dims) — autopilot-leaning
- AutopilotProposalCards lead: "I can make these from what you gave me." (SP1: prefill composer on click. SP3: stage a full kit.)
- Composer stays for explicit asks. Feed-me demoted to a quiet "add more" entry.
- CoverageMeter shows near-complete; remaining gaps still nudge.

**Unit boundaries:** each component reads one slice of the advisor contract and renders it. State selection lives only in `AdaptiveCreateSurface`. No component computes coverage or state itself.

## 6. Batch video ingestion UX (entry shell in SP1, full behavior in SP2)

Today a video upload **is** a content trigger — it auto-clips immediately. The new model **breaks that**: ingestion defaults to the library, not instant clips. This is a deliberate behavior change; show a one-time hint.

### Routing model — KB feed is never a choice
Every video ingested (upload, YouTube, Zoom) **always** transcribes → chunks → feeds the KB (voice + dimension signal). The user never asks for that — Context Is King. The only real choice is the **action**:

| Action | Meaning |
|---|---|
| **Clip now** | Run the clip pipeline immediately (today's behavior). |
| **Stockpile** | Lands in the library. Autopilot clips + proposes later; user confirms before anything posts. |
| **Context only** | Feeds KB, never produces public content (private Zoom calls, sensitive material). |

### What the user sees
1. **One drop zone** accepts the whole mixed batch — file uploads + pasted YouTube links + Zoom links together. Not separate uploaders.
2. A **tray** lists each item: thumbnail + detected type + status (fetching / transcribing / ready).
3. Echo states the implicit truth once: "Adding these to your knowledge — they'll teach me your voice and what you talk about."
4. **Agentic per-item routing (default):** Echo proposes a route per item (rich keynote → clip-now suggestion, recurring Zoom → context, rest → stockpile). Each item shows its proposed action as a chip; tap to change (Clip now / Stockpile / Context only).

### SP1 vs SP2 split for this surface
- **SP1:** the entry affordance + the drop-tray UI shell so the page is whole. Runs against current upload behavior or a thin stub.
- **SP2:** per-item routing reasoning, deferred-ingestion backend, the library store, and the dimension classifier. Lights up the tray's intelligence.

### Data implication (SP2, recorded here for contract continuity)
Ingest row gains `routing: 'clip_now' | 'library' | 'context_only'` and `ingest_to_kb` (always true). Library rows = the set autopilot scans for future clipping.

## 7. Backend — KB-advisor endpoint (echome-platform-v2)

`GET /api/kb/advisor` — authenticated, GA (all users), read-only.

### Response contract
```ts
{
  state: 'empty' | 'thin' | 'rich',
  coverage: {
    work:          { covered: boolean, strength: number /*0-1*/, sampleCount: number },
    industry:      { covered: boolean, strength: number, sampleCount: number },
    interests:     { covered: boolean, strength: number, sampleCount: number },
    personal:      { covered: boolean, strength: number, sampleCount: number },
    relationships: { covered: boolean, strength: number, sampleCount: number },
    voice:         { covered: boolean, strength: number, sampleCount: number }
  },
  nudge: {
    headline: string,
    subhead: string,
    actions: Array<{
      label: string,
      type: 'voice' | 'ingest' | 'create',
      payload?: Record<string, unknown>   // e.g. composer prefill text, or ingest target
    }>
  },
  proposals: Array<{                       // rich state only; [] otherwise
    id: string,
    title: string,
    rationale: string,
    kitType: string,
    sourceRefs: string[]
  }>
}
```

### Behavior
- **Precompute + cache** keyed by `user_id + kb_hash` (reuse the `voice_profiles.kb_hash` pattern). Recompute on KB change; serve cache on load → instant.
- **Deterministic gate fallback:** if cache is cold or the model call failed, compute `state` + `coverage` deterministically and return a curated nudge for the bucket. The page is never broken; `proposals` may be `[]` in fallback.
- **One cheap model call** to generate `nudge` copy + (rich) `proposals`, against the content methodology. Never on the request path when cache is warm.
- **Read-only.** No writes to KB, billing, auth, email. Respects sensitive-path rules.
- **Contract stability:** SP3 swaps the *producer* to the Echo v2 engine; the response shape above does not change.

### Coverage computation (tier-1)
- `work.strength` from presence/length of `profile_role`, `profile_topics`, `public_profiles.fields`.
- `voice.strength` from count of voice recordings + writing samples + `voice_profiles` presence and `total_chunks`.
- `industry/interests/personal/relationships` coarse from `voiceContext.recurringThemes`, `coreBeliefs`, and `chunks.source_type` diversity. Marked tier-1 approximate; SP2 classifier replaces.

## 8. Data flow

1. Load → `AdaptiveCreateSurface` calls `GET /api/kb/advisor` (cached).
2. Response → pick state → render hero + CoverageMeter + nudge/proposals + tiles.
3. Capability tile / nudge action click → prefill composer (`type: 'create'`) or open ingest flow (`type: 'ingest'`) or start voice capture (`type: 'voice'`).
4. Voice capture / ingest completes → KB changes → `kb_hash` changes → advisor recomputes (async) → next load reflects new coverage.

---

## 9. Error handling

- Advisor request fails (network / 5xx) → FE falls back to a static `thin`-equivalent layout (composer + voice button + generic capability tiles). Page always usable.
- Cold cache → BE returns deterministic gate result; FE renders normally with curated copy and empty `proposals`.
- Voice capture / ingest errors surface inline in the tray per item; one failed item never blocks the batch.

## 10. Testing

- **Env:** develop → Vercel preview wired to staging backend (Supabase hyab). Founder account `ara.mamourian@tryechome.com` exists on staging.
- **State smokes:** seed KB coverage to land each of empty / thin / rich; assert correct state + nudge render.
- **Advisor:** unit-test deterministic gate + coverage computation against fixture KB states; assert contract shape; assert fallback path returns valid response when the model call is stubbed to fail.
- **FE:** component tests per component reading a fixture advisor contract; integration test that `AdaptiveCreateSurface` selects the correct state.
- **Cold-cache:** verify page renders from deterministic fallback with the model call disabled.

---

## 11. Scope boundaries

- **SP1 (this spec):** adaptive page + CoverageMeter + KB-advisor endpoint (tier-1 coverage, GA) + nudge/proposal rendering + voice-first hero + capability-tile reframe + VideoLibraryDrop entry/tray shell. Proposals = prefill suggestions.
- **SP2 (BE):** long-form video library deferred ingestion + per-item routing reasoning + dimension classifier (tier-2 coverage) + `routing`/`ingest_to_kb` columns.
- **SP3 (BE, on Echo v2):** autopilot kit generation + AI scheduling + confirm-then-post; advisor producer → v2 engine; proposals graduate from prefill to staged kits.

---

## 12. Constraints

- Release policy: develop → staging smoke → main; founder soak decides main. No autonomous main push.
- Sensitive paths untouched (auth, stripe, middleware, email, webhooks). Advisor is read-only.
- No em dashes in user-facing copy.
- RLS disabled on any new backend-only tables (none in SP1).
